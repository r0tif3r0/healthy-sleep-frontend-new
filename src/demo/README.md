# Демо-режим

Показ фронтенда без бэкенда: service worker перехватывает запросы к API и отвечает подготовленными данными. Приложение об этом не знает — работают те же экраны, тот же `apiClient`, та же охрана маршрутов, что поедут в прод.

Включается только переменной `VITE_DEMO=1`. Без неё демо-код не попадает в сборку вообще: импорт динамический и лежит внутри условия, которое сборщик вычисляет статически.

## Запуск локально

```bash
npm run dev:demo
```

Плашка «Демо» внизу слева: вход за пациента, врача или администратора и кнопка сброса. Пароль не проверяется — настоящей авторизации здесь нет.

## Выкладка на Vercel

1. Запушить ветку в GitHub (или GitLab / Bitbucket).
2. На vercel.com — **Add New → Project**, импортировать репозиторий.
3. **Root Directory** — `healthy-sleep-frontend-new`. Это обязательно: репозиторий содержит несколько проектов.
4. Framework Preset определится как Vite. Команду сборки менять не нужно — её задаёт `vercel.json` (`npm run build:demo`).
5. Переменные окружения не нужны: всё необходимое лежит в `.env.demo`, который читается по `--mode demo`.
6. Deploy.

`vercel.json` уже настроен: все маршруты переписываются на `index.html` (иначе прямая ссылка на `/app/stats` даст 404), а `mockServiceWorker.js` отдаётся без кэша.

Ссылка Vercel публична. Кому попадёт ссылка, тот и зайдёт — если это нежелательно, есть парольная защита на платном тарифе.

## Что внутри

| Файл | Что делает |
|---|---|
| `data.json` | ночи терапии |
| `db.ts` | состояние в памяти вкладки, справочник приборов, врач, администратор |
| `handlers.ts` | ответы на все эндпоинты, которые дёргает приложение |
| `start.ts` | запуск service worker |
| `panel.ts` | плашка «Демо» — обычный DOM, приложение о ней не знает |

Состояние живёт в памяти: правка профиля, отвязка пациента, загрузка архива работают по-настоящему, но перезагрузка страницы возвращает демо к исходному виду. Так следующий зритель всегда видит целую картину.

## Откуда данные

Показатели настоящие — выгружены из локальной базы после разбора реальных архивов пяти приборов (те, что лежат в `../../../CPAP_data`). Имена, почты и телефоны вымышленные, персональных данных здесь нет.

Даты хранятся смещением в днях от сегодняшнего дня, а не абсолютной датой: иначе демо протухло бы через месяц и открывалось на пустом периоде.

**Раскладка по календарю синтетическая.** В настоящих архивах ночи разрежены на полтора года, и в тридцатидневное окно попадало три-четыре штуки — на показе это выглядит как пустая база. Поэтому ночи разложены подряд, с редкими пропусками; значения показателей при этом приборные, не выдуманные.

Шесть пациентов подобраны так, чтобы показать разные состояния интерфейса:

| Пациент | Что показывает |
|---|---|
| Смирнова | образцовая терапия, приверженность около 90% |
| Ковалёв | провальная приверженность, много коротких ночей |
| Гущина | недавно под наблюдением, данных две недели |
| Фадеева | AirCurve 10 — часть индексов прибор не отдаёт, в таблице прочерки |
| Лазарев | месяц без выгрузки: период сам подтягивается к последним данным |
| Тимофеев | данных нет вовсе — пустое состояние |

## Как удалить

```bash
rm -rf src/demo public/mockServiceWorker.js vercel.json .env.demo
```

Затем:

1. В `src/main.tsx` убрать блок с комментарием «демо-режим» и оставить голый `render()`.
2. В `package.json` удалить скрипты `build:demo` и `dev:demo` и ключ `msw.workerDirectory`.
3. В `.claude/launch.json` (в корне репозитория) удалить конфигурацию `healthy-sleep-demo`.

`msw` остаётся в devDependencies — он нужен тестам.

Проверка, что ничего не осталось:

```bash
npm run build && npm run lint && npm test
grep -r "demo" src/ --include=*.ts --include=*.tsx
```
