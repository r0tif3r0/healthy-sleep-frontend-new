# Здоровый сон — фронтенд

Веб-приложение дистанционного мониторинга СИПАП-терапии: пациент загружает данные с карты памяти прибора, врач видит динамику показателей.

Написано с нуля вместо `healthy-sleep-frontend-develop`. Серверная часть (`healthy-sleep-backend-main`) не менялась ни одной строкой.

## Запуск

```bash
npm ci
cp .env.example .env.local   # и поправьте адреса
npm run dev
```

| Команда | Что делает |
|---|---|
| `npm run dev` | Дев-сервер на 5173 |
| `npm run dev:demo` | То же, но с демо-данными вместо бэкенда |
| `npm run build` | Проверка типов и сборка в `dist/` |
| `npm run build:demo` | Сборка демоверсии для показа заказчику |
| `npm run lint` | ESLint |
| `npm test` | Тесты (Vitest) |

### Переменные окружения

```
VITE_API_BASE_URL=https://api.healthysleep.sixhands.co
VITE_PUBLIC_URL=https://healthysleep.sixhands.co
```

`VITE_PUBLIC_URL` — адрес самого сайта. Из него строится ссылка, которую пациент копирует для врача: при смене домена её не придётся искать в коде.

### Деплой

`Dockerfile`, `nginx.conf` (порт 5173), `docker-compose.yml` (проброс 25810:5173) и `.gitlab-ci.yml` перенесены из прежнего проекта без изменений, чтобы существующий пайплайн заработал на новом каталоге.

## Демо для показа

Есть режим, в котором приложение работает без бэкенда: запросы перехватывает service worker и отвечает подготовленными данными. Нужен для показа заказчику — например, на Vercel. Как запустить, как выложить и как потом удалить одной командой — в [src/demo/README.md](src/demo/README.md).

## Стек

React 18, Vite 5, TypeScript strict, Tailwind CSS 4 (токены в `@theme`), TanStack Query 5, axios, react-router-dom 6, react-hook-form + zod, Chart.js 4, react-day-picker 9, date-fns 4, JSZip. Тесты — Vitest + Testing Library + MSW.

Компоненты собственные: готовый UI-кит и был причиной прежнего «шаблонного» вида.

## Структура

```
src/
├── app/          провайдеры (запросы, тема, авторизация), маршруты и охрана
├── pages/        по файлу на маршрут, только композиция
├── widgets/      оболочка приложения, графики, виджеты показателей, печатный отчёт
├── features/     авторизация, статистика, загрузка, профиль, пациенты
├── shared/       api, ui, icons, lib, config, hooks
├── assets/       иллюстрации и шрифты
└── styles/       токены, базовые стили, печатная форма отчёта
```

Расчёты и форматирование вынесены в `shared/lib/metrics.ts` и `shared/lib/format.ts` и покрыты тестами: раньше те же формулы жили внутри разметки, и приверженность из карточки не сходилась с приверженностью из отчёта.

## Единицы измерения

Задаются в `shared/lib/format.ts` и больше нигде:

| Показатель | Единица |
|---|---|
| Давление, минимальное и максимальное давление, EPR | `мм рт. ст.` |
| AHI, AI, OAI, CAI, HI, UAI | `событий/час` |
| Плавный старт (Ramp) | `мин` |
| Утечки | `л/мин` |
| Длительность | часы и минуты |
| Приверженность | `%` |

Давление подписано в **мм рт. ст.** по решению заказчика: так оно приводится в заключениях центра. Находка Н-14 снята, менять подпись не нужно.

## Дизайн

Пиксельный эталон — дизайн-канвас с семью артбордами. Исходники макетов лежат в `../design/*.dc.html`, лист дизайн-системы — `../design/System.dc.html`.

Ночной синий — оболочка (сайдбар, вход, лендинг), голубой — данные, оранжевый — действие и «ниже нормы», зелёный — норма. Оранжевый нигде не используется декоративно: иначе он перестаёт читаться как сигнал на графике.

## Отчёт для врача

Собирается из данных и печатается средствами браузера (кнопка «Выгрузить отчёт» → печать → «Сохранить как PDF»). Разметка отчёта — `widgets/report/PatientReport.tsx`, печатные стили — `styles/report.css`.

Так решены сразу четыре находки: отчёт не обрезается по нижнему краю листа, не зависит от ширины окна врача, остаётся текстом, а не картинкой, и не молчит при пустых данных — кнопка просто недоступна.

jsPDF не используется: встроить в него кириллицу нечем. `@fontsource` отдаёт woff, разбитый на подмножества, и ни в одном файле нет одновременно кириллицы, латиницы и цифр, а брать системный шрифт Windows нельзя по лицензии.

## Что ждёт текста от заказчика

В интерфейсе стоят видимые скобки — их нельзя выдумывать:

- контакт центра в инструкции по загрузке (`features/upload/UploadInstructions.tsx`);
- телефон и почта в подвале лендинга (`pages/LandingPage.tsx`);
- итоговая редакция политики обработки персональных данных (`pages/LegalPage.tsx`).

## Роль администратора

Управление пользователями остаётся в панели администрирования на стороне сервера: REST-интерфейса для создания и правки учётных записей у бэкенда нет. Экран `/app/admin` объясняет это и ведёт в панель.

## Проверка на реальных данных

Прогнаны все пять архивов из `../CPAP_data/Распакованные` через живой бэкенд:

| Прибор | Файлов | Ночей разобрано | Период данных |
|---|---|---|---|
| ResMed AirSense S10 | 1101 | 71 | 27.08.2023 — 06.11.2024 |
| ResMed AirSense S11 | 97 | 14 | 30.05.2024 — 13.06.2024 |
| ResMed AirCurve 10 | 99 | 3 | 23.04.2021 — 26.04.2021 |
| ResVent iBreeze 20a | 396 | 6 | 05.12.2023 — 10.12.2023 |
| Weinmann Prisma 20A | 2 | 6 | 26.09.2024 — 12.10.2024 |

Повторная загрузка того же архива у всех пяти добавляет ноль ночей — интерфейс
показывает «Новых ночей нет», а не «успешно» (находка Н-25).

Что дал прогон, кроме подтверждения:

- **Поле `mode` не приходит ни от одного прибора.** Оно было в типе прежнего
  фронтенда, и строка «Режим» в настройках прибора всегда показывала «Нет данных».
  Поле убрано из типа и из карточки.
- **У ResMed AirCurve 10 поля `oai`, `cai`, `uai` и `epr` приходят как `null`** —
  это находка Н-29, подтверждённая на реальных данных. Типы допускают null,
  в таблице такие ячейки показываются прочерком.
- **Утечки у ResMed бывают меньше единицы** (0,7 л/мин), и округление до целого
  превращало их в «0» — читалось как «утечек нет». Показываем один знак после запятой.
- **Архив S10 заканчивается ноябрём 2024**, то есть почти на два года раньше
  текущей даты. Период по умолчанию сам подтянулся к последним данным — экран
  показал «8 окт — 6 ноя 2024» вместо «данных нет» (находка Н-28 в деле).
